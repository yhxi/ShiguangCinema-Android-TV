# 时光影院 · LibreTV（非官方）

同一个 APK 适用于 Android 手机和 Android TV。手机使用竖屏、触控和播放器触控进度条；电视使用横屏、遥控器焦点和方向键。最低 Android 6.0（API 23）。项目不含原生架构专属库，因此不区分 ARM/AMD64 安装包。

首次打开时可以输入任意 LibreTV 服务端地址和访问密码，也可以选择内置的 `tvoracle` 或 `tvworker` 预设。正式发布版需要手动输入密码；本机调试版可通过忽略文件启用一键登录。成功连接过的地址和会话保存在本机，不同服务端的片源与直播源分别保存。旧版 v1.0.0-B APK 曾包含预设密码，公开发布前应更换旧密码。

首页仅展示合并去重后的最新、热门剧集，顶部提供点播、直播、搜索、历史、片源、设置入口；有本地播放记录时以海报卡片显示「最近观看」，点选会从上次进度续播。旧记录缺封面时会用剧名向已配置的片源补查。

构建：安装 JDK 25 与 Android SDK API 37.0，在项目根目录执行 `gradlew.bat :app:assembleDebug`。产物位于 `app/build/outputs/apk/debug/app-debug.apk`。

## 0.16.0 变更

- **新增「设置 → 网络诊断」**。点进去自动跑一遍，逐段计时，最后给结论。手机上分五层：

  | 层 | 测什么 | 能看出 |
  |---|---|---|
  | ① 本机网络 | WiFi / 移动数据 / VPN 通道 / 系统估算带宽 | 很多「服务端慢」其实是走了 VPN |
  | ② 跨境链路 | DNS（3 次取最好）、TCP、TLS 握手、首字节、**DNS 交叉验证** | 每次请求的固定成本；DNS 是否被污染 |
  | ③ 服务端接口 | `/api/status`、`/api/douban`、`/api/search`、`/api/detail` | 扣掉链路成本后的「服务端真正干活时间」 |
  | ④ 封面图 | 豆瓣直连 vs 服务端代理 | 两张路的实际差距，首页 24 张差多少秒 |
  | ⑤ 采集站 | 逐个 `testSource`，4 并发 | 谁在拖后腿、有几个连不上 |

- 每个接口都同时显示「总耗时」和「处理 ≈ N ms」（= 总耗时 − 链路合计），这样能分清是**路远**还是**对方慢**。
- **DNS 交叉验证**用公共 DoH（`doh.pub`）把同一域名再解析一遍，和系统结果对比；不一致直接标红，提示本机 DNS 很可能被污染 —— 国内访问境外服务时这是最常见的「能连但巨慢」原因。
- 底部「复制报告」把整份结果（含时间、服务端、每项耗时）复制到剪贴板，方便贴出来求助。

## 0.15.3 变更（提速）

实测数据：服务端在 Cloudflare（`tvoracle.20350720.xyz` → 172.67.134.253 / 104.21.6.156），
一个只做本地密码校验的 `/api/auth` 也要 **1.0~1.3 秒**才返回 —— 说明慢的大头是**跨境链路的固定成本**，不是服务端逻辑。

- **海报改成直连，不再走服务端代理**。以前每张图都请求 `/api/proxy?url=...`，等于国内设备 → Cloudflare → 图床，一张图两个跨境往返。实测豆瓣图床带 `Referer: https://movie.douban.com/` 直连返回 200（0.45s），不带直接 418 —— 所以现在按 host 加 Referer 直连，失败再回退代理。
- **直连失败按 host 记黑名单**。有的采集站把图放在国内连不上的图床，服务端却能访问；这类图如果每次都先试直连，要白等一次超时才回退，比改动前还慢。现在失败一次就记住，本次进程内直接走代理。
- **图片下载线程 3 → 6**。24 张海报原来分 8 批，即使每张 0.5 秒也要 4 秒才铺满。
- **搜索结果 3 分钟内复用**（同一关键词 + 同一组源）。搜一次要服务端把每个采集站问一遍，看完一部点返回再搜同一部是常见动作，不必再等一遍。
- **详情页 5 分钟内复用**（同 vodId + 同源）。从列表反复进出同一部剧、来回换源比较时不再每次转圈。

## 0.15.2 变更

- **「最近观看」一部剧只留一条**。以前按播放地址去重，同一部剧每看一集就多一条 —— 海贼王 1134 / 1133 / 1132 三张卡并排。现在按「剧名归一化」聚合，只保留最近播放的那一集（「最近观看」的语义本来就是「接着看」，回看更早的集走详情页选集）。老数据在读取时自动收敛并写回一次，升级后立刻生效，不用等下次播放。
- **点「选集」不再干等**。两个改动：
  - **面板先弹出来**。以前是先 toast 一句「正在获取剧集列表…」然后干等网络，慢网下十几秒没反应，看着像没点上。现在立刻打开一个过渡面板，写明「正在获取《海贼王》的剧集列表… 当前第 1133 集」，查到就地换成完整网格。
  - **先单独查已知源**。从历史/详情进来都带着 `vodId + sourceUrl`，直接查这一个源的详情就能精确命中（1 次请求）。以前不管有没有 `vodId` 都是先 `api.search()` 把所有采集站打一遍、再逐个查详情（最多 8 个），光搜索就要好几秒 —— 这才是「请求了半天」的主因。现在搜索只在已知源没命中时才跑，候选也从 8 个降到 5 个。
- 修一个因此暴露的卡死：静默回查正在跑时点「选集」，以前 `resolveEpisodes` 直接 return、`onDone` 永不回调，过渡面板会一直转。现在把后来者的回调排队，回查结束时一并通知。

## 0.15.1 变更

- **修「不点选集就永远不跳片尾」**。从观看历史 / 单集直链进播放页时 `urls` 只有一条，而 `checkOutroSkip()` 靠 `currentIndex + 1 in urls.indices` 判断有没有下一集 —— 只有一条就认定「这是最后一集」，于是片尾曲照放；点一下「选集」触发整季回查后，片尾才开始自动跳（海贼王看到第 1033 集，被判成只有一集）。现在起播 4 秒后**静默回查一次整季**，并且只走「分集列表里必须包含当前播放地址」的精确命中；失败不弹任何提示，用户察觉不到。
- 回查拿到整季后不再 `setMediaItems` 重建播放列表，改成用 `addMediaItems` 把「前面」「后面」两段插到当前媒体项两侧 —— 正在播的这一条原地不动，**画面不闪、不重新缓冲**。
- 片尾判断加了一道兜底：列表仍只有一条时再补一次静默回查（总共最多 2 次），不做无限重试。

## 0.15.0 变更

- **新增「追剧」**。详情页多了「＋ 加入追剧」，记下加入那一刻这部剧共几集；回到首页时后台静默比对一次（6 小时一检），集数变多就在首页入口上标出「追剧·N 新」，列表里标「更新至 X 集 · 新增 Y 集」。纯本地比对，不依赖服务端推送。「追剧」页可手动点「检查更新」，长按取消追剧。
- **新增外挂字幕**。「更多 → 外挂字幕」可用系统文件选择器挂 srt / ass / ssa / vtt，挂上立即生效、不用重进播放页。字幕**按播放地址逐集保存**（同一部剧每集字幕文件不同，不能串），格式靠读文件头嗅探（SAF 返回的 `content://` 地址常常没有扩展名）。换集时菜单标题会跟着变成那一集自己的字幕名。
- 顺手修掉一处隐患：手动「移除外挂字幕」之后 `hasError` 会被复位，标题栏颜色也会跟着回到正常色，避免上一次播放失败的红字残留在画面上。

- **硬解失败降级不再污染全局设置**：以前硬解挂了直接改全局 `decodeMode`，导致所有片源都变软解、全都变卡。现在只把**这一部剧**标成软解（`softDecodeFor(剧名)`），「解码方式」菜单里显示「（本剧软解）」。

## 0.13.0 变更

- **换源不再丢进度**。以前进度只按播放地址记（`pos:<url hash>`），而换源就是换 URL —— 换完源同一集又得从头拖，偏偏换源就是因为原源卡了。现在除了按地址记，**再按「剧名 + 集号」记一份**：先查地址，查不到就用剧名+集号兜底。播完（`STATE_ENDED`）时两份一起清，不会出现「换源重看从片尾开始」。（同名不同版本的剧会共用一份记录，例如动画版和真人版同名，这是这个方案的已知边界。）
- **亮度记住了**。`window.attributes.screenBrightness` 只对当前窗口有效，之前每次进播放页都回系统亮度，滑动手势调完就白调；现在存进 `Prefs`，进页面自动恢复。
- **新增定时关闭**：「更多 → 定时关闭」可选 30 / 60 / 90 分钟后自动暂停，菜单上显示剩余分钟，到点暂停并亮出控制条。
- **新增方向锁**：「更多 → 方向」可在「自动旋转 / 已锁定」之间切换。上一版做的竖屏片源自动转竖屏，侧躺看时会被误转，锁上就不动了；解锁时立刻按当前画面比例归位。
- **进度条上画出片头片尾**：白色竖线 = 片头结束点，琥珀色竖线 = 片尾开始点（`MarkedSeekBar`）。以前标完只能靠「到点自动跳」，看不到标在哪、也看不出标没标对；在「跳过」面板里改完立刻刷新。
- **详情页补上主演**：`VideoInfo` 里 `year / area / actor / remarks` 一直解析着，但只渲染了简介。现在多一行「主演：…」。

## 0.12.1 变更

- **首页入口图标改成自绘**。之前用的是 `▷ ▣ ✦ ⌕ ◉ ☆ ✚ ⚙` 这些字体符号，它们来自不同 Unicode 区块，各家字体的字面大小、笔画粗细、基线位置都不一样 —— 真机上「搜索」的 `⌕` 和「设置」的 `⚙` 明显比「电影」的 `▷` 小一圈、笔画也细，摆在同一排里像是没渲染出来；部分设备还会把 `⚙` 当 emoji 画成彩色。现在统一用 `HomeIconView` 在 24×24 坐标系里描边绘制再整体缩放（搜索=放大镜、设置=齿轮、电影=播放三角、剧集=屏幕+三角、综艺=四角星、直播=同心圆、继续=时钟、片源=加号），八个图标笔画一致、重心一致，也不再有缺字风险。
- **暂停时画面正中浮出播放按钮**：点中间暂停后，继续播的入口就在手指刚点的地方，不用再低头去底部找那个小图标；播放中它一直隐藏，不挡画面。
- **倍速提到一级菜单**：手机底部控制条现在是「倍速 / 选集 / 跳过 / 全屏 / 锁定 / 更多」。倍速按钮在 1.0 倍时只显示「倍速」，改了倍速会显示「倍速 X1.5」，和遥控器操作栏里的标签同步。

## 0.12.0 变更

- **拖进度条不再「弹回去」**。根因是 500ms 的轮询一直在用播放位置覆盖进度条：手指还在拖，进度已经被拉回去，看着就像拖不动。现在按下就掐掉轮询，松手把目标位置记进 `pendingSeek`（seek 落地前 `currentPosition` 还是旧值，不记就会先回跳一帧再跳到目标）。
- **进度落盘改成 30 秒一次**。`upsertHistory` 要把整份历史数组序列化后重写，之前每 5 秒一次，长剧久播时会有周期性卡顿；现在轮询照旧、写盘节流，`onStop`/退出仍然立即写。
- **画面手势**（手机）：
  - 轻点**中间竖带** → 播放 / 暂停；轻点**左右两侧** → 唤出 / 收起控制条；
  - **双击左右** → 快退 / 快进 10 秒；
  - **左半屏上下滑** → 亮度，**右半屏上下滑** → 音量，顶部浮一个小胶囊显示 `亮度 62%`；
  - 滑动不会被误判成点击（位移 > 28dp 且以纵向为主才进滑动模式）。
- **竖屏片源自动转竖屏**。manifest 默认横屏（剧集都是横屏），竖屏短剧在横屏下两侧会留出巨大黑边；现在按 `videoSize` 判断后自动切 `SENSOR_PORTRAIT / SENSOR_LANDSCAPE`。
- **播放页补安全区**：横屏时挖孔/机身圆角会压住进度条两端，现在只给片名和控制条加 `displayCutout` 内边距，画面本身继续铺满。
- **硬解失败自动切软解重试**：解码类错误先直接把 `decodeMode` 置软解、记下当前位置后重启播放页，能从原地接着放；不会反复重启（软解模式下不再进这个分支）。软解也失败才提示换源。
- **手机首页换成单层 RecyclerView**（头部占满整行的 header item + 海报网格）。0.11.0 里「ScrollView 套一个撑到内容全高的 GridView」虽然解决了「头部钉死」，但 GridView 的视口等于全部内容高度，所有行都会被当成屏内一次性布局，复用失效；30 条没事，滑到两三百条内存和帧率会线性变差。现在只渲染可见行，触底续加载也改成按可见位置判断。电视端仍用原来的 GridView（遥控器焦点是逐行接管的，不值得为它冒险）。
- **海报内存缓存上限跟堆挂钩**：`min(48MB, 堆 / 8)`。电视盒子常见只有 192MB 堆，固定 48MB 会吃掉四分之一。

- **搜索与设置页修好**：列表行不再抢焦点，点哪一行都能响应（之前手机上点「播放设置」等行完全没反应）。

- **P1 搜索历史逐条删除**：以前只能整批清空，手滑搜错的词永远占着第一条。现在每行右侧一个「✕ 删除」，遥控器左右键在关键词和删除之间移动。

- **P2 最近观看长按删除**：首页「最近观看」卡片长按（遥控器可用菜单键）删除单条记录，不用再去「继续」页整批清空。

- **P2 后台播放通知**：退出播放页后仍在放时，通知栏常驻一条「暂停 / 继续 / 停止」，点通知回播放页。没引 media3-session，用最朴素的广播实现，不额外增加依赖。

## 0.5.0 变更

- **修：从观看历史进去，选集只剩 1 集**（明明 1180 集）。原因：历史只存了"当前这一集"的地址，播放器拿到的就是 1 个 url。现在历史记录额外保存干净剧名 / 采集站地址 / vodId / 集号；播放器点「选集」时若只有 1 个地址，会自动回查整季（有 vodId 直接查详情，老记录用剧名搜），恢复后停在原来那一集，地址对不上就按集号推算。旧记录无需手动处理，走搜索兜底。
- **切分类时保持旧页面**：以前换「电影/剧集/综艺」会先清空列表再重画，切换那一两秒显示"正在整理最新热播剧集…+重试推荐"，像加载失败。现在旧列表原样留着，数据到手才一次性换页；失败提示一句、页面停在原分类。切换请求走独立槽位，不会和「加载更多」互相取消。
- **加载提示不再是模态弹窗**：改为顶部一颗小胶囊（转圈 + 文案），不挡内容、不抢焦点。取消改由 BACK 键负责（只取消当前槽位的请求）；清理缓存这类不可取消的动作按 BACK 会提示稍等。顺带去掉翻页时那个"加载更多…"弹窗。
- **遥控器 CH+ / CH- 翻屏**（同时兼容 PageUp / PageDown）：列表按可见行数跳、网格按整行跳，以前只能一格一格按上下。
- **起播缓冲三档**：设置 → 播放设置 → 起播缓冲（快速 / 均衡 / 稳定），对应 ExoPlayer `minBufferMs` 8s / 20s / 40s，弱网可调"稳定"，想秒开选"快速"。

## 0.4.2 变更（体感/手感包）

- **返回首页不再跳回顶部**：以前从播放器或详情页返回，整页重建、网格归零，你在第 6 行挑的片子看完回来又回到第 1 行。现在按 `lastVisibleIndex` 原位恢复，并把焦点交回网格。
- **翻页不再整屏闪**：加载更多改为 `notifyDataSetChanged` 原地补行，不再重建整页（以前滚到底会闪一下、焦点掉回顶部入口栏）。
- **海报二级缓存**：新增磁盘缓存（`cacheDir/poster_cache`，50MB，LRU 淘汰，JPEG 85，存的是已降采样的小图），并给同一张图做并发去重（以前同一张海报被几个格子同时请求就下载几次）。冷启动二次进入不再满屏灰格子逐个变亮，断网时也能看到上次的海报。
- **换服务器不再清空海报缓存**：`ImageLoader.updateApi()` 只换绑定，不重建加载器。
- **换页 120ms 淡入**：只在页面类型发生变化时淡入，数据刷新（加载更多/封面回填）不淡入，避免滚动时满屏闪。
- **「清理缓存」真的清磁盘了**：以前只显示播放缓存占用、点清理并不删（显示 800MB，清完还是 800MB）。现在清海报磁盘 + 播放分片缓存，删除放后台（几 GB 分片在老盒子上要几秒），弹窗不可取消以免"显示已取消但磁盘还在删"。
- **播放中不清分片缓存**：`PlaybackCache.playerOpened/Closed` 计数，有播放器活着时跳过并提示 —— 之前 release `SimpleCache` 会让播放器下次读片直接崩。

## 0.4.1 变更

- **每个子页都有「← 返回主页」**：设置、服务器设置、播放设置、首页栏设置、片源管理、导入/添加片源、文件浏览、搜索结果、搜索页、详情、直播、继续观看等 16 个页面，右上角固定同一颗按钮，一键回首页。以前只有遥控器 BACK 键能回去，按钮看不见（详情页更是一个回退入口都没有）。
- **自动聚焦不抢在返回上**：顶部返回按钮带标记，进页面时的自动聚焦会跳过它，焦点仍落在列表/输入框/海报上，不会一进来就选中「返回」。

## 0.4.0 变更

- **启动不再弹「正在连接服务器」**：先把首页骨架画出来，后台静默连接，连上后自动补上推荐；失败只在顶部留一行可点「重新连接」的说明，不打断操作。
- **修复误报**：切页面 / 请求被后一次顶掉时，协程取消会被当成网络错误弹出「网络失败：StandaloneCoroutine was cancelled」，现在按正常取消处理，静默退出。
- **播放页选集**：操作栏新增「选集」（排在第一位），按当前集高亮、遥控器上下左右选择、自动滚到当前集；切换时按该集自己的续播点起播。手机端顶栏也拆出独立的「选集」按钮。

- **手机首页入口改 3×2**：六个入口不再横向裁切，窄屏一屏可见。
